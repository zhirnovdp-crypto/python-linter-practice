# Статический анализ Python-кода с помощью Ruff

## Цель и объект проверки

Цель работы — настроить линтер, найти и исправить нарушения в исходном коде, а затем проверить, как отключение одного правила влияет на результат.

Объект проверки — репозиторий `python-linter-practice`. Учебный проект рассчитывает стоимость заказа в целых рублях. На вход подаются цена за единицу, количество товаров и, при необходимости, процент скидки. Если после скидки получается дробная сумма, программа округляет её вниз до целого рубля. Для запуска программы и тестов достаточно стандартной библиотеки Python.

| Файл или каталог | Назначение |
| --- | --- |
| `shop/__init__.py` | Обозначает каталог как пакет Python. |
| `shop/pricing.py` | Проверяет входные значения и рассчитывает стоимость заказа. |
| `shop/__main__.py` | Разбирает аргументы командной строки для запуска через `python -m shop`. |
| `tests/test_pricing.py` | Содержит семь тестов расчёта на `unittest`. |
| `examples/long_line.py` | Содержит длинную строку для демонстрации отключения `E501`. |
| `pyproject.toml` | Хранит настройки Ruff. |
| `reports/` | Содержит полные выводы команд для трёх этапов. |

## Выбор и настройка линтера

Для работы выбран Ruff 0.14.10. Он умеет проверять стиль, находить неиспользуемые импорты и переменные и проверять порядок импортов одной командой. Параметры закреплены в `pyproject.toml`, чтобы проверка воспроизводилась у других участников.

Работа выполнена в существующем окружении `.venv` с Python 3.12.14 и Ruff 0.14.10. Команды ниже рассчитаны на Bash. Начните в корне репозитория `python-linter-practice`.

```bash
source .venv/bin/activate
export NO_COLOR=1
python --version
ruff --version
```

На первых двух этапах использовалась такая конфигурация.

```toml
[tool.ruff]
target-version = "py312"
line-length = 88

[tool.ruff.lint]
select = ["E501", "E711", "F401", "F841", "I001"]
```

`target-version` задаёт целевую версию Python для анализа. `line-length` задаёт лимит в 88 символов для правила `E501`. В `select` перечислены пять правил практической работы.

## Этап 1. Первоначальная проверка

На первом этапе в калькулятор намеренно внесены пять нарушений. Команда запускает проверку репозитория с указанным файлом настроек.

```bash
ruff check --config pyproject.toml .
printf 'Код завершения %s\n' "$?"
```

Ruff сообщил `Found 5 errors.` и завершился с кодом `1`. В каждой диагностике указаны код правила, файл, строка и столбец. В журнал записаны версии инструментов, полный вывод команды и код завершения. [Журнал первоначальной проверки](reports/01_initial_check.txt)

## Этап 2. Анализ и исправления

Позиции в таблице относятся к исходному коммиту `19ccdd9`. Все пять нарушений исправлены вручную.

| Правило | Позиция | Что нашёл Ruff | Как исправлено |
| --- | --- | --- | --- |
| `I001` | `shop/__main__.py:1:1` | Локальный импорт стоял перед импортом из стандартной библиотеки. | `import argparse` перенесён в начало. Относительный импорт отделён пустой строкой. |
| `E501` | `shop/__main__.py:6:89` | Строка с описанием команды заняла 137 символов при лимите 88. | Вызов `ArgumentParser` и описание разбиты на строки. Python объединяет соседние строковые литералы в скобках. |
| `F401` | `shop/pricing.py:1:8` | Модуль `math` импортирован и нигде не используется. | Удалён `import math`. |
| `F841` | `shop/pricing.py:12:5` | Переменной `currency` присвоена строка, но её значение нигде не читается. | Удалено присваивание `currency = "руб."`. |
| `E711` | `shop/pricing.py:13:28` | Для сравнения с `None` использовался оператор `==`. | Условие заменено на `discount_percent is None`, чтобы проверять идентичность объекту `None`. |

После исправлений повторно запущен Ruff с теми же настройками. Затем запущены тесты.

```bash
ruff check --config pyproject.toml .
python -m unittest discover -s tests -v
git diff 19ccdd9 8ef6de3 -- shop
```

Ruff вывел `All checks passed!` и вернул код `0`. Все семь тестов прошли. Они проверяют расчёт без скидки и со скидкой, округление вниз, скидки 0 и 100 процентов, нулевое количество, отрицательную цену или количество и скидку за пределами допустимого диапазона. [Журнал после исправлений](reports/02_after_fixes.txt)

## Этап 3. Отключение правила E501

В секцию `[tool.ruff.lint]` добавлено `ignore = ["E501"]`. Правило `E501` отвечает за превышение лимита длины строки. В `examples/long_line.py` специально оставлена строка длиной 119 символов при лимите 88. Этот файл входит в обычную проверку репозитория.

```bash
ruff check --config pyproject.toml .
printf 'Код завершения %s\n' "$?"

ruff check --config pyproject.toml --select E501 examples/long_line.py
printf 'Код завершения %s\n' "$?"

printf 'import math\n' | ruff check --config pyproject.toml -
printf 'Код завершения %s\n' "$?"

python -m unittest discover -s tests -v
python -m shop 120 3 --discount 25
```

| Проверка | Фактический результат |
| --- | --- |
| Обычный запуск Ruff по репозиторию | `All checks passed!`, код `0`. |
| Контрольный запуск на примере с `--select E501` | `E501 Line too long (119 > 88)` в `examples/long_line.py:3:89`, код `1`. |
| Проверка фрагмента `import math` через стандартный ввод | Ruff обнаружил `F401`, код `1`. |
| Модульные тесты | Все 7 тестов прошли, код `0`. |
| Запуск калькулятора | Выведено `270`, код `0`. |

Параметр `--select E501` включает правило для одного запуска. В обоих запусках используется один и тот же файл с длинной строкой. Разница в выводе показывает эффект `ignore`. Проверка через стандартный ввод отдельно подтверждает, что `F401` работает с финальной конфигурацией. [Журнал финальной проверки](reports/03_final_check.txt)

## Как повторить первые два этапа

Git хранит исходную версию в коммите `19ccdd9`, а исправленную версию с пятью активными правилами — в `8ef6de3`. Из корня репозитория с активированным окружением можно выгрузить оба снимка во временный каталог. Такой способ позволяет проверять снимки, оставаясь на текущей ветке.

```bash
replay_dir=$(mktemp -d)
mkdir -p "$replay_dir/01" "$replay_dir/02"
git archive 19ccdd9 | tar -x -C "$replay_dir/01"
git archive 8ef6de3 | tar -x -C "$replay_dir/02"

(
    cd "$replay_dir/01" || exit
    ruff check --config pyproject.toml .
    printf 'Код завершения %s\n' "$?"
)
(
    cd "$replay_dir/02" || exit
    ruff check --config pyproject.toml .
    printf 'Код завершения %s\n' "$?"
    python -m unittest discover -s tests -v
)
git log --oneline -3
```

На первом снимке ожидаются пять нарушений и код `1`. На втором ожидаются успешная проверка Ruff с кодом `0` и семь пройденных тестов. Этап 3 воспроизводится командами из предыдущего раздела в финальной версии проекта.

## Вопросы для устной защиты

1. **Что такое статический анализ?** Проверка исходного кода без запуска анализируемой программы.
2. **Почему выбран Ruff?** Один инструмент проверяет стиль, импорты и ряд ошибок в Python-коде. Набор правил задаётся в конфигурации.
3. **Где хранятся настройки линтера?** В `pyproject.toml`, в секциях `[tool.ruff]` и `[tool.ruff.lint]`.
4. **Что задаёт `target-version = "py312"`?** Версию Python, для которой Ruff анализирует код.
5. **Что означают коды завершения Ruff `0` и `1`?** Код `0` означает успешную проверку, код `1` — наличие нарушений.
6. **Чем отличаются `F401` и `F841`?** `F401` относится к неиспользуемому импорту, а `F841` — к неиспользуемой локальной переменной.
7. **Зачем использовать `is None`?** Оператор `is` проверяет, является ли значение именно объектом `None`.
8. **Как отключено правило `E501`?** Его код добавлен в список `ignore` в секции `[tool.ruff.lint]`.
9. **Как проверить эффект отключения?** Запустить обычную проверку, затем указать `--select E501` для файла с длинной строкой. Сообщение появится во втором запуске.
10. **Зачем запускать тесты после линтера?** Линтер проверяет исходный текст по правилам, а тесты запускают код и сверяют фактические результаты расчёта с ожидаемыми.
